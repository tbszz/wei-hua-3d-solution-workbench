# 照片现场

PRD 场景 R4：销售拿手机拍一张客户现场，在地面上点一个已知尺寸的矩形，网页反算出相机，把 AGV 按真实比例放进照片里，导出一张图发给客户。

和 `demo/` 分开，是一个独立的网页。车型和模型直接用 `demo/src/catalog.js`、`demo/src/vehicle.js`，静态目录同样是 `../data`。

## 运行

```bash
cd photo
npm install
npm run dev
```

打开 <http://127.0.0.1:5181>，按三步走：

1. **照片**：上传一张现场照片，或者点「用示例照片」。
2. **标定**：按 A → B → C → D 顺着矩形的边点 4 个角，可以拖动微调，拖动时左上角有放大镜。填 AB、BC 两条边长。右边给出标定误差，叠一张 1 m 地面网格，用眼睛核对。
3. **放车**：选 AGV1 或 Z1，在照片上拖动车，点地面把车放过去，滚轮或滑块改朝向，亮度滑块对一下照片的曝光。导出 PNG，长边最多 3840 像素。

误差超过 3% 时不能进入第 3 步，也不能导出。

```bash
cd photo
npm test
```

示例照片是程序生成的（demo_data），不是客户现场。重新生成需要 numpy 和 Pillow，大约 1 分钟：

```bash
python photo/tools/make_sample.py
```

输出 `data/photo/sample-floor.jpg`，旁边的 `sample-floor.json` 记着真实相机和 4 个角的像素位置，用来核对标定结果。

## 怎么算的

代码在 `src/calibrate.js`，纯数学，不依赖 three.js，可以在 node 里跑。

1. 4 个点求地面到照片的单应矩阵 H。
2. 假设主点在照片中心、像素是正方形，未知数只剩焦距。由 H 的两列正交、等长给出焦距的初值，再求相机姿态。
3. 焦距、旋转、平移一共 7 个参数，用 LM 最小化 4 个点的重投影误差。
4. 把点的 4 个像素反投到地面，量出 4 条边长，和填的边长比较，取最大的相对误差作为标定误差。
5. 换成 three.js 的 `PerspectiveCamera`：位置、四元数、竖直视场角。地面是 y = 0，矩形 A 在原点，AB 沿 +x。

**两条边都要填。** 4 个点正好够解单应，只给一条边时没有多余的条件，反算误差永远是 0，点歪了也发现不了。两条边加上「矩形」这个约束，才有可以检验的余量。

会直接拒绝、给出中文提示的情况：点不够 4 个、点在照片外、两个点太近、三点几乎共线、四边形交叉或凹、边长不是正数、透视太弱（近乎正对地面俯拍，焦距解不出来）、点到了地平线以上。焦距换算到 35 mm 等效后不在 13–200 mm 之间时只给警告。

## 精度

在 4000 × 3000 的合成照片上，给 4 个点加随机像素噪声，每档跑 300 次：

| 点击误差（σ） | 边长误差中位数 | 边长误差 95% | 焦距误差中位数 | 相机高度误差 95% |
|---|---|---|---|---|
| 1 px | 0.38% | 1.05% | 0.1% | 1.3 cm |
| 2 px | 0.75% | 1.94% | 0.3% | 2.6 cm |
| 4 px | 1.45% | 4.04% | 0.6% | 5.3 cm |
| 8 px | 3.09% | 7.99% | 1.2% | 11.2 cm |

也就是说，在 4000 像素宽的原图上把角点点准到 2 像素以内，误差基本在 3% 线以内。所以页面上有放大镜。

在示例照片上手点 4 个角：误差 1.0%，相机高度 2.33 m（真值 2.30 m），等效焦距 25.1 mm（真值约 24.9 mm），重投影 0.8 px。

单元测试用 three.js 的相机投影造数据，和 `calibrate.js` 不共用公式：无噪声时焦距、高度能还原到 1e-6；±0.5 px 噪声下边长误差 < 0.5%；边长填错、角点点偏、三点共线、点太近等退化情况都有可读的报错。

## 限制

- **地面要平。** 模型假设 4 个点和车都在同一个平面上。有坡度、台阶、积水反光的地面，误差会算不准，车也会浮起来或陷下去。
- **不处理镜头畸变。** 手机主摄的畸变一般能忽略；超广角（0.5×）、鱼眼、运动相机的照片边缘弯曲明显，算出来的误差会偏大，车也会对不齐。
- **主点按照片中心算。** 裁剪过的照片主点不在中心，相机高度和俯角会错，所以要用原图。
- **没有遮挡。** 车永远画在照片最前面，车前面的柱子、货架不会挡住它。摆位置时要避开。
- **车按名义尺寸画**，参数化调尺寸在 `demo/` 里，这里还没接。
- **光照不匹配。** 环境光和阴影方向是固定规则（光从相机侧后上方来），只有一个亮度滑块；照片里的阴影方向和色温要靠人眼对。
- 透视太弱（正对地面俯拍、矩形太小太远）会被拒绝，换个角度斜着拍。
- 客户照片只在浏览器里处理，不上传到任何地方。
